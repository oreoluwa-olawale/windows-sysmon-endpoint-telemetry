# Process Creation Analysis

## Purpose

This document records selected Sysmon Event ID 1 process creation events collected during a controlled Windows 10 laboratory exercise.

All activities were deliberately generated by the investigator. No malware was used.

## Event 1: Notepad

### Process Relationship

```text
cmd.exe
    |
    └── notepad.exe
```

### Sysmon Evidence

Sysmon Event ID 1 recorded the creation of notepad.exe during the controlled laboratory exercise.

### Observed Details

- Process: notepad.exe
- Parent process: cmd.exe
- User: DESKTOP-5D4PUL7\tkb
- Process ID: 8340
- Command line: notepad.exe
### Interpretation

The process relationship observed was:

cmd.exe → notepad.exe

This was a known-good activity because Notepad was deliberately launched during the laboratory exercise. The event demonstrates how Sysmon Event ID 1 can be used to identify the process, its parent process, user context, command line, and process ID.

## Event 3: PowerShell Get-Service

### Process Relationship

```text
cmd.exe
    |
    └── powershell.exe
```

Sysmon Evidence

Sysmon Event ID 1 recorded the creation of powershell.exe during the controlled laboratory exercise.

Observed Details

- Process: powershell.exe
- Parent process: cmd.exe
- User: DESKTOP-5D4PUL7\tkb
- Process ID: 8556
- Command line: powershell.exe -NoProfile -Command "Get-Service"

### Interpretation

The process relationship observed was:

cmd.exe → powershell.exe

The PowerShell process executed Get-Service, which displays information about Windows services.

This activity was deliberately generated during the laboratory exercise and is therefore known-good in this context. However, PowerShell and service enumeration can also appear during legitimate administration or during security investigations, so the command alone is not proof of malicious activity.

## Overall Findings

The controlled exercises demonstrated how Sysmon Event ID 1 can provide useful endpoint telemetry for process investigation.

The collected events allowed the investigator to identify:

- The process that was created
- The parent process that launched it
- The user context
- The process ID
- The command line used to launch the process

The exercises also demonstrated that process activity must be interpreted in context. A PowerShell process, for example, is not automatically malicious. The analyst must examine the command, parent process, user, timing, related activity, and other available telemetry.

## Investigation Limitations

This laboratory exercise used deliberately generated, known-good activity. It does not represent a confirmed security incident or malware investigation.

The exercise also relied primarily on Sysmon Event ID 1. A real endpoint investigation would normally correlate process creation with other telemetry such as network connections, file creation, authentication events, scheduled tasks, services, and additional Sysmon events.

## Conclusion

This exercise demonstrated the basic workflow for using Sysmon process creation telemetry to establish process relationships and investigate command-line activity on a Windows endpoint.
